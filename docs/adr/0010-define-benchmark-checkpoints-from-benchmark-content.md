# Define benchmark checkpoints from benchmark meaning

Plebdev Bench treats **Benchmark Checkpoint** identity as a function of benchmark meaning: benchmark content plus execution and scoring semantics that can change what a run measured. Limiting checkpoints to prompts, fixtures, rubrics, metadata, and scoring specs would make exploratory iteration easier, but harness prompt wiring, retry behavior, extraction logic, workspace scoring, runtime adapters, and signal assessment can also alter outcomes; default comparisons and **Leaderboards** must not silently mix runs across those semantic changes.
